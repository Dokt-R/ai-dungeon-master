# Story 2.3: D&D 5.1 SRD Ruleset Integration

**Status:** Draft

---

## Story

**As a** player, **I want** the AI DM to be aware of the D&D 5.1 SRD rules, **so that** its rulings and descriptions are accurate and fair.

## Acceptance Criteria

1. The AI's system prompt or context is primed with the D&D 5.1 SRD ruleset (e.g., via RAG or context priming).
2. The AI can correctly answer a direct question about a specific SRD rule (e.g., "How much damage does a longsword do?").
3. The AI's narrative descriptions correctly reference SRD mechanics (e.g., correctly describing a spell's effect or a monster's abilities).

### Data Models
**SRD Data Models:**
```python
class Monster(BaseModel):
    """SRD monster data structure."""
    monster_name: str = Field(..., description="Official monster name")
    armor_class: int = Field(..., description="Monster's armor class")
    hit_points: str = Field(..., description="Hit point range or average")
    actions: Optional[str] = Field(None, description="Monster's actions and abilities")

class Spell(BaseModel):
    """SRD spell data structure."""
    spell_name: str = Field(..., description="Official spell name")
    level: int = Field(..., description="Spell level (0-9)")
    description: str = Field(..., description="Complete spell description and mechanics")

class Weapon(BaseModel):
    """SRD weapon data structure."""
    weapon_name: str = Field(..., description="Official weapon name")
    damage: str = Field(..., description="Damage dice and type")
    properties: Optional[str] = Field(None, description="Weapon properties and special rules")
```

**Tool Response Models:**
```python
class RulesQuery(BaseModel):
    """Query structure for SRD rules requests."""
    query_type: Literal["monster", "spell", "weapon", "item"] = Field(..., description="Type of SRD query")
    name: str = Field(..., description="Name to look up in SRD database")
    context: Optional[str] = Field(None, description="Additional context for the query")

class RulesResponse(BaseModel):
    """Response structure for SRD rules queries."""
    query_type: str = Field(..., description="Type of query processed")
    name: str = Field(..., description="Original query name")
    found: bool = Field(..., description="Whether the item was found in SRD")
    data: Optional[Dict[str, Any]] = Field(None, description="SRD data if found")
    error: Optional[str] = Field(None, description="Error message if query failed")
```

### API Specifications
- **SRD Query Endpoints (Optional):** `GET /api/srd/{type}/{name}`
  - Request: Path parameters for type (monster/spell/weapon) and name
  - Response: `RulesResponse` model with SRD data
  - Error Response: `{"error": "Not found", "query": "monster_name"}`
- **Integration Points:** RulesEngine integration with DM Graph tools
- **Database:** SQLite connection to srd_database.sqlite
- **Caching:** In-memory caching for frequently queried SRD data

### Component Specifications
- **RulesEngine Component** (`packages/backend/components/rules_engine.py`):
  - SQLite database interface for SRD rule queries
  - Provider pattern implementation for different rule types
  - Connection pooling and query optimization
  - Error handling for database connection issues
  - Integration with LangGraph as callable tools
- **SRD Database Initialization** (`data/srd_database.sqlite`):
  - Pre-populated with essential D&D 5.1 SRD monsters and spells
  - Optimized indexes for common query patterns
  - Data validation against official SRD sources
  - Migration system for SRD updates
