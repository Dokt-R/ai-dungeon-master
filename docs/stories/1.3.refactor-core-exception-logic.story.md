# Story 1.3: Refactor Core Exception Logic

## Status

Approved

## Story

**As a** developer,
**I want** to enhance our custom exceptions to carry structured data and eliminate the generic `handle_error` function,
**so that** our error handling logic is more specific, powerful, and easier to maintain.

## Acceptance Criteria

1. [ ] The `handle_error` function is completely removed from `packages/shared/error_handler.py`.
2. [ ] `CustomException`, `ValidationError`, and `NotFoundError` are updated to accept optional `error_code` and `details` arguments in their `__init__` methods.
3. [ ] A new `AIAPIError(CustomException)` is created to represent failures from external AI services.
4. [ ] The logic previously in `handle_error` is now fully contained within the FastAPI exception handlers and the Discord decorator.

## Tasks / Subtasks

- [ ] Task 1 (AC: 1)
  - [ ] Delete the `handle_error` function from `packages/shared/error_handler.py`
- [ ] Task 2 (AC: 2)
  - [ ] Modify the `__init__` method of `CustomException` to accept optional `error_code` and `details` parameters
  - [ ] Modify the `__init__` method of `ValidationError` to accept optional `error_code` and `details` parameters
  - [ ] Modify the `__init__` method of `NotFoundError` to accept optional `error_code` and `details` parameters
- [ ] Task 3 (AC: 3)
  - [ ] Create a new `AIAPIError` class that inherits from `CustomException`
  - [ ] Add appropriate docstring for the new exception class
- [ ] Task 4 (AC: 4)
  - [ ] Update FastAPI exception handlers to use the exception's properties directly instead of calling `handle_error`
  - [ ] Update Discord decorator to use the exception's properties directly instead of calling `handle_error`
- [ ] Task 5 (Validation)
  - [ ] Run tests and manually verify that errors are still handled correctly after removing the central function
  - [ ] Verify that the new `AIAPIError` can be raised and handled properly in both FastAPI and Discord contexts

### Implementation Guidance

1. In `packages/shared/error_handler.py`:
   - Locate and delete the `handle_error` function (likely around lines 30-43 based on previous analysis)
   - Update the exception classes to accept new parameters:
     ```python
     class CustomException(Exception):
         """Base class for custom exceptions."""
         def __init__(self, message: str, error_code: str = None, details: dict = None):
             super().__init__(message)
             self.message = message
             self.error_code = error_code
             self.details = details

     class ValidationError(CustomException):
         """Exception raised for validation errors."""
         def __init__(self, message: str, error_code: str = "VALIDATION_ERROR", details: dict = None):
             super().__init__(message, error_code, details)

     class NotFoundError(CustomException):
         """Exception raised for not found errors."""
         def __init__(self, message: str, error_code: str = "NOT_FOUND", details: dict = None):
             super().__init__(message, error_code, details)
     ```
   - Add the new `AIAPIError` class:
     ```python
     class AIAPIError(CustomException):
         """Raised when an external AI API call fails."""
         def __init__(self, message: str, error_code: str = "AI_API_ERROR", details: dict = None):
             super().__init__(message, error_code, details)
     ```

2. In `packages/backend/main.py`:
   - Update the exception handlers to use the exception properties directly:
     ```python
     @app.exception_handler(ValidationError)
     async def validation_exception_handler(request: Request, exc: ValidationError):
         return JSONResponse(
             status_code=400,
             content={
                 "error": {
                     "code": exc.error_code or "VALIDATION_ERROR",
                     "message": exc.message,
                     "details": exc.details
                 }
             }
         )
     
     # Similar updates for other exception handlers
     ```

3. In `packages/bot/cogs/*.py` files:
   - Update the Discord error handler decorator to use exception properties directly instead of calling `handle_error`
