# Story 3.1: Implement Structured & Correlated Logging

## Status

Approved

## Story

**As a** developer,
**I want** our logs to be structured (e.g., JSON) and contain a correlation ID,
**so that** I can easily trace a request's entire lifecycle through different services and debug complex issues more effectively.

## Acceptance Criteria

1. [ ] A structured logging library (like `structlog`) is integrated and configured in both `packages/backend/main.py` and `packages/bot/main.py`.
2. [ ] A FastAPI middleware is implemented that generates a unique correlation ID for each incoming request.
3. [ ] The correlation ID is automatically included in all log messages generated during the processing of that request.

## Tasks / Subtasks

- [ ] Task 1 (AC: 1)
  - [ ] Add `structlog` to the project's requirements in `requirements.txt` and `pyproject.toml`
  - [ ] Configure `structlog` in `packages/backend/main.py` with JSON formatting
  - [ ] Configure `structlog` in `packages/bot/main.py` with JSON formatting
- [ ] Task 2 (AC: 2)
  - [ ] Create a FastAPI middleware that generates and stores a correlation ID for each request
  - [ ] Ensure the middleware is properly registered with the FastAPI application
- [ ] Task 3 (AC: 3)
  - [ ] Modify the logging configuration to automatically include correlation IDs in log messages
  - [ ] Verify that correlation IDs are included in all log messages during request processing
- [ ] Task 4 (Validation)
  - [ ] Make an API request and inspect the console logs to confirm they are in JSON format
  - [ ] Verify that all logs for that request share the same correlation ID
  - [ ] Test that bot logs also use the structured format

### Implementation Guidance

1. Dependency Management:
   - Add `structlog` to `requirements.txt`:
     ```
     structlog>=24.1.0
     ```
   - Add `structlog` to `pyproject.toml`:
     ```toml
     [project.dependencies]
     structlog = ">=24.1.0"
     ```

2. In `packages/backend/main.py`:
   - Configure `structlog` with JSON rendering:
     ```python
     import structlog
     import uuid
     from fastapi import Request
     
     # Configure structlog
     structlog.configure(
         processors=[
             structlog.contextvars.merge_contextvars,
             structlog.processors.add_log_level,
             structlog.processors.StackInfoRenderer(),
             structlog.dev.set_exc_info,
             structlog.processors.TimeStamper(fmt="iso"),
             structlog.processors.JSONRenderer()
         ],
         wrapper_class=structlog.BoundLogger,
         context_class=dict,
         logger_factory=structlog.PrintLoggerFactory(),
         cache_logger_on_first_use=False
     )
     
     # Create middleware for correlation ID
     @app.middleware("http")
     async def correlation_id_middleware(request: Request, call_next):
         # Generate correlation ID
         correlation_id = str(uuid.uuid4())
         
         # Bind correlation ID to structlog context
         structlog.contextvars.bind_contextvars(correlation_id=correlation_id)
         
         # Add correlation ID to response headers (optional)
         response = await call_next(request)
         response.headers["X-Correlation-ID"] = correlation_id
         
         # Clear context vars after request
         structlog.contextvars.clear_contextvars()
         
         return response
     ```

3. In `packages/bot/main.py`:
   - Configure `structlog` similarly to the backend:
     ```python
     import structlog
     
     # Configure structlog
     structlog.configure(
         processors=[
             structlog.contextvars.merge_contextvars,
             structlog.processors.add_log_level,
             structlog.processors.StackInfoRenderer(),
             structlog.dev.set_exc_info,
             structlog.processors.TimeStamper(fmt="iso"),
             structlog.processors.JSONRenderer()
         ],
         wrapper_class=structlog.BoundLogger,
         context_class=dict,
         logger_factory=structlog.PrintLoggerFactory(),
         cache_logger_on_first_use=False
     )
     ```

4. In other modules:
   - Replace standard logging calls with structlog:
     ```python
     import structlog
     
     logger = structlog.get_logger()
     
     # Instead of logging.info("message")
     logger.info("message")
     
     # With context
     logger.info("message", extra_key="extra_value")
     ```

### Testing Standards

- **Test file location**: 
  - New tests may be needed in `tests/integration/backend/` for the middleware
  - Existing tests should continue to pass with the new logging configuration
  
- **Test standards**: 
  - Ensure that after the change, all log messages are in structured JSON format
  - Verify that correlation IDs are correctly generated and included in logs
  - Confirm that existing functionality is not broken by the logging changes
  
- **Testing frameworks and patterns to use**:
  - Use `pytest` for testing
  - Use `unittest.mock` to test logging behavior if needed
  - Manual testing to verify JSON log format and correlation IDs
  
- **Specific testing requirements for this story**:
  - Test that API requests generate logs with correlation IDs
  - Test that all logs during a single request have the same correlation ID
  - Test that bot logs also use the structured format
  - Verify that log messages are properly formatted as JSON
  - Confirm that the middleware doesn't interfere with request processing
