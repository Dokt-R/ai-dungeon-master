### Refactoring Performed

**Architecture Improvements Recommended:**
1. **Global State Management** - The global `prompt_manager` instance is initialized at module import time, creating potential testing and dependency issues
   - **Why**: Import-time side effects make testing difficult and violate dependency injection principles. Global state can cause issues with test isolation and makes the system harder to reason about in concurrent scenarios.
   - **How**: Implement dependency injection pattern to allow test-specific prompt manager instances. Consider using context managers or explicit initialization methods.
   - **Impact**: Will improve testability, maintainability, and support for multi-tenant scenarios.

2. **Token Estimation Enhancement** - Current token counting uses simple character division (line 97 in prompts.py: `return len(filled_content) // 4`)
   - **Why**: Inaccurate token estimation can lead to unexpected API costs, rate limiting issues, and prompt truncation failures. Different languages and content types have varying token densities.
   - **How**: Integrate proper tokenizer (tiktoken library) for accurate token counting that matches the AI provider's tokenization method.
   - **Impact**: Will provide more reliable cost estimation, prevent API failures, and optimize prompt length for different content types.

3. **Caching Strategy** - No caching mechanism for filled templates
   - **Why**: Repeated template filling with same variables wastes computation
   - **How**: Implement LRU cache with template ID and variables as cache key

4. **Hardcoded Timestamp** - Health endpoint uses hardcoded timestamp (line 260 in health_api.py)
   - **Why**: Inconsistent with other dynamic timestamps in the same file
   - **How**: Use `datetime.utcnow().isoformat() + "Z"` for consistency
