# Story 2.2: Secure Error Message Handling

## Status

Ready for Review

## Story

**As a** user,
**I want** to receive helpful error messages without seeing sensitive backend information,
**so that** my data and the system's integrity are protected.

## Acceptance Criteria

1. [x] No raw exception messages from unexpected errors are ever returned in an API response or sent in a Discord message.
2. [x] The generic exception handlers for both FastAPI and Discord provide a fixed, sanitized message (e.g., "An unexpected error occurred.").
3. [x] Error messages for custom, known exceptions (`ValidationError`, `NotFoundError`, `AIAPIError`) are confirmed to be safe for display.

## Tasks / Subtasks

- [x] Task 1 (AC: 1, 2)
  - [x] Review the implementation of the FastAPI exception handlers to confirm they meet the acceptance criteria
  - [x] Review the implementation of the Discord exception handlers to confirm they meet the acceptance criteria
  - [x] Ensure that generic exceptions never result in raw error messages being sent to users
- [x] Task 2 (Code Review)
  - [x] Search the codebase for any other instances of `str(e)` being passed to a user-facing output
  - [x] Refactor them to use safe, custom messages
- [x] Task 3 (AC: 3)
  - [x] Review error messages for `ValidationError`, `NotFoundError`, and `AIAPIError` to confirm they are safe for display
  - [x] Update any error messages that might expose sensitive information
- [x] Task 4 (Validation)
  - [x] Trigger an unexpected error (e.g., `TypeError`) and confirm the user sees the generic, sanitized message
  - [x] Verify that known exception types still provide helpful but safe messages

### Implementation Guidance

1. In `packages/backend/main.py`:
   - Review the generic exception handler to ensure it returns a sanitized message:
     ```python
     @app.exception_handler(Exception)
     async def generic_exception_handler(request: Request, exc: Exception):
         logger.error(f"Unhandled exception: {exc}", exc_info=True)
         return JSONResponse(
             status_code=500,
             content={
                 "error": {
                     "code": "INTERNAL_SERVER_ERROR",
                     "message": "An unexpected error occurred. Our team has been notified."
                 }
             }
         )
     ```
   - Ensure custom exception handlers return user-safe messages:
     ```python
     @app.exception_handler(ValidationError)
     async def validation_exception_handler(request: Request, exc: ValidationError):
         return JSONResponse(
             status_code=400,
             content={
                 "error": {
                     "code": exc.error_code or "VALIDATION_ERROR",
                     "message": exc.message,  # Should be a user-safe message
                     "details": exc.details
                 }
             }
         )
     ```

2. In `packages/shared/error_handler.py`:
   - Review the Discord error handler to ensure it sends sanitized messages:
     ```python
     except (ValidationError, NotFoundError, AIAPIError) as e:
         logger.warning(f"Handled exception in command {func.__name__}: {e}")
         await _safe_send_message(interaction, str(e), ephemeral=True)  # str(e) must be user-safe
     except Exception as e:
         logger.error(f"Unhandled exception in command {func.__name__}: {e}", exc_info=True)
         # Fallback message defined in decorator: "An unexpected error occurred. Please contact an administrator."
         await _safe_send_message(interaction, fallback_message, ephemeral=True)
     ```

3. Codebase-wide review:
   - Search for any instances of `str(e)` or `str(exception)` in user-facing code
   - Replace with safe, predefined messages or messages from custom exceptions that are designed to be user-safe
   - Safe message example: "Invalid input format" instead of raw database error
   - Unsafe message example: "Database connection failed: postgres://user:password@localhost/db"
