# Story 2.2: Secure Error Message Handling

## Status

Approved

## Story

**As a** user,
**I want** to receive helpful error messages without seeing sensitive backend information,
**so that** my data and the system's integrity are protected.

## Acceptance Criteria

1. [ ] No raw exception messages from unexpected errors are ever returned in an API response or sent in a Discord message.
2. [ ] The generic exception handlers for both FastAPI and Discord provide a fixed, sanitized message (e.g., "An unexpected error occurred.").
3. [ ] Error messages for custom, known exceptions (`ValidationError`, `NotFoundError`, `AIAPIError`) are confirmed to be safe for display.

## Tasks / Subtasks

- [ ] Task 1 (AC: 1, 2)
  - [ ] Review the implementation of the FastAPI exception handlers to confirm they meet the acceptance criteria
  - [ ] Review the implementation of the Discord exception handlers to confirm they meet the acceptance criteria
  - [ ] Ensure that generic exceptions never result in raw error messages being sent to users
- [ ] Task 2 (AC: 3)
  - [ ] Review error messages for `ValidationError`, `NotFoundError`, and `AIAPIError` to confirm they are safe for display
  - [ ] Update any error messages that might expose sensitive information
- [ ] Task 3 (Code Review)
  - [ ] Search the codebase for any other instances of `str(e)` being passed to a user-facing output
  - [ ] Refactor them to use safe, custom messages
- [ ] Task 4 (Validation)
  - [ ] Trigger an unexpected error (e.g., `TypeError`) and confirm the user sees the generic, sanitized message
  - [ ] Verify that known exception types still provide helpful but safe messages

### Implementation Guidance

1. In `packages/backend/main.py`:
   - Review the generic exception handler to ensure it returns a sanitized message:
     ```python
     @app.exception_handler(Exception)
     async def generic_exception_handler(request: Request, exc: Exception):
         logger.error(f"Unhandled exception: {exc}", exc_info=True)
         return JSONResponse(
             status_code=500,
             content={
                 "error": {
                     "code": "INTERNAL_SERVER_ERROR",
                     "message": "An unexpected error occurred. Our team has been notified."
                 }
             }
         )
     ```
   - Ensure custom exception handlers return user-safe messages:
     ```python
     @app.exception_handler(ValidationError)
     async def validation_exception_handler(request: Request, exc: ValidationError):
         return JSONResponse(
             status_code=400,
             content={
                 "error": {
                     "code": exc.error_code or "VALIDATION_ERROR",
                     "message": exc.message,  # Should be a user-safe message
                     "details": exc.details
                 }
             }
         )
     ```

2. In `packages/shared/error_handler.py`:
   - Review the Discord error handler to ensure it sends sanitized messages:
     ```python
     except (ValidationError, NotFoundError) as e:
         logger.warning(f"Handled exception in command {func.__name__}: {e}")
         await _safe_send_message(interaction, str(e), ephemeral=True)  # str(e) should be user-safe
     except Exception as e:
         logger.error(f"Unhandled exception in command {func.__name__}: {e}", exc_info=True)
         await _safe_send_message(interaction, fallback_message, ephemeral=True)  # Should be generic
     ```

3. Codebase-wide review:
   - Search for any instances of `str(e)` or `str(exception)` in user-facing code
   - Replace with safe, predefined messages or messages from custom exceptions that are designed to be user-safe

### Testing Standards

- **Test file location**: 
  - Existing tests in `tests/integration/backend/` for API error handling
  - Existing tests in `tests/unit/bot/` for bot error handling
  
- **Test standards**: 
  - Ensure that after the change, no sensitive information is leaked in error messages
  - Verify that all error messages are appropriate for end users
  - Confirm that logging still captures full technical details for developers
  
- **Testing frameworks and patterns to use**:
  - Use `pytest` for unit testing
  - Use `unittest.mock` to simulate various error conditions
  
- **Specific testing requirements for this story**:
  - Test that generic exceptions result in sanitized user messages
  - Test that custom exceptions provide helpful but safe messages
  - Verify that no stack traces or technical details are exposed to users
  - Confirm that technical details are still logged for developers
